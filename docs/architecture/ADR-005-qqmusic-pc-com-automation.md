# ADR 005 QQ 音乐 PC COM 自动化作为主播放路线

- 状态：Accepted
- 日期：2026-09-13
- 决策者：项目所有者

## 背景

QQ 音乐 PC 22.41 的窗口可以被识别，但其主界面没有向 Windows UI Automation 暴露可用的语义化后代控件，无法可靠定位搜索、队列与播放按钮。QQ 音乐网页版虽然能探测搜索框，但队列和播放结构不足以形成稳定闭环，项目所有者决定暂缓 Chrome 实际播放。

本机安装同时注册了 32 位 `QQMusicSvr 1.0` COM 类型库。类型库包含当前歌曲、队列枚举、加歌、排序、播放控制和事件等自动化成员；只读原型已在 22.41 上成功激活并读取当前歌曲 ID、队列数量和队列 ID。

## 决策

M5 改为优先实现 Windows PC 连接器，使用 QQ 音乐安装程序注册的本机 COM 自动化服务。Chrome 扩展代码和公共连接器协议继续保留，但网页实际播放进入暂停状态，仅作为未来备用路线。

COM 属于客户端暴露但缺少稳定公开文档的版本敏感接口。连接器必须按 QQ 音乐版本逐项启用能力，未知版本默认只读并安全失败。核心系统仍只通过 ADR 004 的公共连接器协议发送队列和播放命令。

## 安全门槛

- 不注入进程、不读写内存、不修改 QQ 音乐文件，不提取播放 URL 或音频。
- 第一阶段 allowlist 仅包含 `GetCurrentPlaySongID`、`GetPlayItemCount` 和 `EnumPlayItemIDs`。
- 写入与播放阶段只逐项验证 `AddSong`、`SetPlaySequence`、`SetCurrentPlaySongID`、`Play`、`Pause`、`Stop`、`PlayPrev` 和 `PlayNext`。
- `DeleteAll`、下载、上传、登录、收藏变更、歌词写入及其他无关成员不进入连接器。
- 每次队列提交先检查客户端版本、COM 激活、歌曲身份和返回值；超时、歧义或部分失败时停止后续动作并报告实际状态。
- 首次写入测试只使用可恢复的临时测试队列，并由用户明确触发。

## 后果

- PC 客户端成为当前唯一主动开发的实际播放目标，降低同时维护两套脆弱适配器的成本。
- COM 的歌曲数据格式、队列写入语义、错误返回和事件回调仍需实机验证，不能因类型库存在就宣称完整播放已完成。
- Chrome 扩展不是删除或废弃；公共协议保证未来恢复网页路线时不需要改动 AI 选歌与临时队列模块。
- 系统媒体传输控制可作为通用播放状态或基础控制的后备能力，但不能替代精确构造 QQ 音乐临时队列。
