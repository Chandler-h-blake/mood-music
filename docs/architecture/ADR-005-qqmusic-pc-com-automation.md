# ADR 005 评估 QQ 音乐 PC COM 自动化

- 状态：Rejected after integration probe
- 日期：2026-09-13
- 决策者：项目所有者

## 背景

QQ 音乐 PC 22.41 的窗口可以被识别，但其主界面没有向 Windows UI Automation 暴露可用的语义化后代控件，无法可靠定位搜索、队列与播放按钮。QQ 音乐网页版虽然能探测搜索框，但队列和播放结构不足以形成稳定闭环，项目所有者决定暂缓 Chrome 实际播放。

本机安装同时注册了 32 位 `QQMusicSvr 1.0` COM 类型库。类型库包含当前歌曲、队列枚举、加歌、排序、播放控制和事件等自动化成员；只读原型可以激活并调用这些查询。

## 决策

不使用 `QQMusicSvr 1.0` COM 服务控制当前 QQ 音乐客户端。实机复测时，QQ 音乐 22.41 正在播放但没有启动 `QQMusicSvr.exe`；由探测器临时启动的服务返回空的当前歌曲和队列。这证明自动化对象可调用，却不能证明它与现代客户端播放状态联动。

PC 客户端仍是 M5 的优先目标。后续只读验证已证明 Windows 系统媒体会话能够读取实际播放与歌曲信息；基础控制仍需单步验证，并需单独寻找可验证的歌曲定位与队列构造方式。Chrome 扩展代码和公共连接器协议继续保留，但网页实际播放维持暂停。

## 安全门槛

- 不注入进程、不读写内存、不修改 QQ 音乐文件，不提取播放 URL 或音频。
- COM 探测 allowlist 仅包含 `GetCurrentPlaySongID`、`GetPlayItemCount` 和 `EnumPlayItemIDs`。
- 不启用 `AddSong`、`SetPlaySequence`、`SetCurrentPlaySongID`、`Play` 或任何 COM 写入与播放方法。
- `DeleteAll`、下载、上传、登录、收藏变更、歌词写入及其他无关成员不进入连接器。
- 每次队列提交先检查客户端版本、COM 激活、歌曲身份和返回值；超时、歧义或部分失败时停止后续动作并报告实际状态。
- 探测输出必须说明服务是否由客户端预先启动；临时独立服务不得报告为播放就绪。

## 后果

- PC 客户端仍是当前主动开发的实际播放目标，但 COM 路线不再继续。
- 类型库存在或方法调用成功不能作为客户端集成证据；必须观察到真实播放状态才允许声明能力。
- Chrome 扩展不是删除或废弃；公共协议保证未来恢复网页路线时不需要改动 AI 选歌与临时队列模块。
- 系统媒体传输控制成为下一项只读验证对象，但即使通过，也不能替代精确构造 QQ 音乐临时队列。
