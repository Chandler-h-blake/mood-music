# ADR 002 使用 QQ 音乐网页版连接器控制播放

- 状态：Accepted
- 日期：2026-09-08
- 决策者：项目所有者

> 2026-09-13 补充：Chrome 扩展继续作为优先实现的稳定播放路径；新增的 QQ 音乐 PC 连接器路线与共享协议见 ADR 004。本 ADR 的网页连接器决策仍然有效。

## 背景

独立 Web 页面受浏览器同源策略和操作系统权限限制，不能直接读取 QQ 音乐登录态，也不能可靠控制已安装的桌面客户端。腾讯公开的音乐接口主要出现在特定 IoT 或商业授权场景，不能假设个人项目天然拥有通用的“喜欢”、播放链接和队列控制 API。

可选方案包括：只提供跳转、控制 QQ 音乐桌面 UI、自己播放音频，以及在用户已登录的 QQ 音乐网页中运行浏览器扩展。本 ADR 只决定播放控制方式；“我喜欢”的同步方式由 ADR 003 决定。

## 决策

首版实现 Chrome Extension Manifest V3 播放连接器。连接器在用户主动打开并登录 QQ 音乐网页版后工作，只定位歌曲、触发用户本可执行的播放操作、读取播放状态，并通过本机配对通道与 FastAPI 服务交换版本化消息。

播放连接器不得提取或发送 QQ Cookie、密码、受保护播放 URL 或原始音频。用户手动粘贴给本机后端、用于只读同步的 Cookie 由 ADR 003 单独约束。页面能力必须运行时协商，未知页面结构必须 fail closed。

## 备选方案比较

| 方案 | 选择 | 原因 |
| --- | --- | --- |
| 浏览器扩展控制 QQ 音乐网页版 | 采用 | 与 Web 技术栈一致，可隔离页面适配且不需要处理音频流 |
| 纯网站直接跨站控制 | 不采用 | 受同源策略限制，无法获得所需页面权限 |
| Windows UI Automation 控制桌面版 | 暂缓 | 精确队列控制和元素稳定性未知，更新后容易失效 |
| 官方商业或 IoT 接口 | 保留未来可能 | 能力可能更稳定，但需要确认申请资格、使用场景和费用 |
| 自己播放 QQ 音频 | 不采用 | 涉及播放授权、会员鉴权、内容保护和分发边界 |

## 技术约束

- Content Script 负责页面适配；Background Service Worker 负责扩展生命周期与本机连接。
- 所有 DOM 选择器和页面能力探测集中在适配器中，不散落到业务代码。
- 本机通信绑定 `127.0.0.1`，使用一次性配对码换取可撤销的安装级令牌。
- 每条命令包含 `protocolVersion`、`requestId` 和超时；重复队列提交必须幂等。
- 扩展返回明确能力，例如 `catalog.search`、`queue.play`、`playback.control` 和 `playback.state`。
- 没有某项能力时，Web UI 隐藏或禁用对应操作并说明回退方式。

## 风险与缓解

- 页面更新：维护兼容性探测、选择器夹具和回归测试；未知版本停止自动化。
- Service Worker 休眠：采用重连和状态恢复，不把未持久化任务只放在扩展内存。
- 操作过快：串行化页面操作并设置可取消超时，不进行高频抓取。
- 账号与隐私：播放扩展不导出登录态，日志只记录去敏后的动作与错误类别。
- 平台条款：项目保持个人自用；任何分发或商业化前重新审查接入方式。
