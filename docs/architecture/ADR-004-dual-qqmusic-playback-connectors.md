# ADR 004 Chrome 与 QQ 音乐 PC 双播放连接器

- 状态：Accepted
- 日期：2026-09-13
- 决策者：项目所有者

## 背景

ADR 002 确定 Chrome Extension Manifest V3 是首条播放控制路径。项目所有者同时希望 MoodMusic 能把相同的 AI 临时队列交给 Windows 上已安装的 QQ 音乐 PC 客户端。桌面客户端没有可假设存在的个人开发者队列 API，而且 UI、控件树和媒体会话能力可能随版本变化，因此不能在验证前把 PC 精确队列控制视为既成能力。

## 决策

MoodMusic 建立与播放器实现无关的本机连接器网关。Chrome 网页连接器优先实现，用于尽快完成稳定闭环；QQ 音乐 PC 连接器作为第二个适配器，先完成可行性探测，再在通过门槛后实现。

两个连接器共享版本化的配对、能力协商、队列快照、幂等命令、播放事件和错误分类。用户可以选择当前连接器，核心搜索、画像和临时队列模块不得依赖 DOM 选择器或 Windows 控件类型。

PC 连接器只允许使用 Windows UI Automation、系统媒体传输控制、媒体键、窗口级公开消息或腾讯明确公开的接口。禁止 DLL 注入、远程线程、进程内 Hook、内存读写、客户端文件修改、协议绕过、播放 URL 提取和音频截获。

## PC 可行性门槛

只有同时满足以下条件，PC 连接器才进入正式实现：

- 能识别目标 QQ 音乐窗口、客户端版本和登录/可操作状态。
- 能以稳定歌曲身份定位至少标题、歌手与版本，不依赖不唯一的屏幕坐标盲点。
- 能按临时队列顺序启动播放，并对未找到、同名多版本和不可播放给出明确结果。
- 能读取足够的当前曲目和播放状态，或明确声明不支持的能力。
- 未知版本、控件歧义、遮挡或超时会安全停止，不误操作其他应用。
- 自动化不读取 Cookie、密码、受保护播放地址或音频内容。

若门槛未通过，产品保留 Chrome 扩展，并提供打开/搜索指定歌曲的人工回退；不得用“看起来点击成功”代替可验证的队列一致性。

## 后果

- 核心连接器协议需要从一开始支持多种连接器类型和能力差异。
- Chrome 与 PC 适配器分别维护兼容性记录和回归样本。
- PC 路线提高桌面使用便利性，但增加 Windows 版本、QQ 音乐版本、控件树和焦点管理的测试成本。
- ADR 001 禁止原生注入的边界保持不变；本决策不是恢复桌面 Mod 方案。
