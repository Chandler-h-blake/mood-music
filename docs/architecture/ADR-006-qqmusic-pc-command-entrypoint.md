# ADR 006 使用 QQ 音乐 PC 客户端命令入口精确点播

- 状态：Accepted with version gate
- 日期：2026-09-13
- 决策者：项目所有者

## 背景

QQ 音乐 22.41 的 UI Automation 控件树不可用，遗留 `QQMusicSvr 1.0` COM 服务与现代客户端播放状态脱节，Windows 系统媒体会话只能提供状态和基础控制，不能指定歌曲。项目要求由后端接口控制 PC 客户端，不采用截图或坐标自动化。

对本机已安装客户端做只读静态检查后，发现 `QQMusic.exe` 支持 `/playbysongid` 命令，并接受数字歌曲 ID。单曲和两首歌曲的实机试验表明：单曲能够精确启动且可由系统媒体状态确认；一次提交多个 ID 不能可靠替换客户端原有的下一首。

## 决策

FastAPI PC 连接器采用组合策略：

1. 通过 QQ 音乐公开歌曲信息响应，把本地保存的 song mid 批量映射为数字歌曲 ID。
2. 使用参数数组调用正在运行或已安装的 `QQMusic.exe /playbysongid`，每次只提交一首，禁止 shell 拼接。
3. 通过 Windows 系统媒体会话回读标题和播放状态，区分“已确认完成”和“已提交但未确认”。
4. 后端保存当前 MoodMusic 临时队列及位置；用户触发下一首或上一首时，按该顺序再次精确点播。
5. 暂不宣称客户端原生整队列写入、自然结束自动续播或最后一首自动停止。

## 安全和兼容性

- 不注入进程、不读写进程内存、不修改客户端文件，不提取音频 URL 或受保护内容。
- 只接受本地数据库中的 14 位字母数字 song mid；映射结果必须是正整数。
- 使用 `subprocess` 参数数组并显式 `shell=False`，歌曲标题和用户输入不进入客户端命令行。
- 优先从运行进程只读获取可执行文件路径；可用 `QQMUSIC_EXE` 显式覆盖，且目标文件名必须为 `QQMusic.exe`。
- `/playbysongid` 并非公开稳定 API。QQ 音乐版本变化后必须重新验证精确点播和状态回读，失败时关闭能力并向用户报告。

## 后果

- PC 连接器现在能从网页经 FastAPI 精确启动临时队列第一首，并可靠处理用户触发的前后切歌。
- 自动续播仍需后端播放结束监视器，M5 尚未满足“最后一首结束后停止”的退出条件。
- Chrome 扩展继续保留为备用协议实现，但不参与当前实际播放。
