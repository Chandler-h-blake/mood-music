# ADR 007：画像任务执行与恢复

日期：2026-10-19。状态：已接受。

当前 FastAPI BackgroundTasks 会随 API 进程退出而丢失，留下无法重试的 running 行；全量重建按数量跳过还会受曲库变化和失败项影响。本次落实系统设计已有的 PostgreSQL 任务表与独立 worker，不引入额外基础设施。

- API 仅持久化 queued 任务，独立 `python -m moodmusic_api.worker` 领取并执行。
- 创建和重试使用事务级 advisory lock，防止并发提交多个活动画像任务。
- worker 用行锁领取 queued 或租约过期的 running 任务，每 15 秒续租，租约 90 秒。旧执行者写入前必须校验持有者和有效期，失去租约即停止。
- 每批画像与 completedSongIds 在同一事务提交。记录初始 songIds、成功与跳过歌曲 ID，重启不按完成数量切片；人工重试清空跳过项。
- 老任务没有 ID 清单时，增量任务根据画像指纹重算，全量任务重新建立 ID 清单并重建未锁定画像；允许重复生成画像版本，避免漏处理。续跑时移出喜欢的未处理歌曲不再计入剩余总量。
- Web 通过最新任务接口恢复进度。重启会接管之前明确提交的任务；暂停、取消、SSE 暂不在本轮交付范围。

启动脚本同时启动 API、worker 和 Web，停止脚本同时停止三者。API 故障不再终止画像；worker 故障最多等待一个租约周期后恢复。没有 worker 时任务保持排队且界面明确显示。
