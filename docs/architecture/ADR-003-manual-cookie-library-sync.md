# ADR 003 使用手动 Cookie 进行“我喜欢”同步

- 状态：Accepted
- 日期：2026-09-10
- 决策者：项目所有者

## 背景

MoodMusic 是仅供项目所有者在个人 Windows 电脑上运行的单用户应用。腾讯没有面向普通个人 Web 应用、可以直接申请并稳定读取 QQ 音乐个人“我喜欢”的通用公开 OAuth API。社区项目普遍通过已登录 Cookie 或模拟二维码登录调用 QQ 音乐内部接口；二维码登录还涉及设备参数、登录协议、凭据刷新和额外维护成本。

首版需要先可靠完成一千至数千首“我喜欢”的分页同步。用户接受从已登录浏览器复制 Cookie 并粘贴到本机应用，因而没有必要把复杂二维码登录作为首版前置条件。

## 决策

首版把“手动 Cookie 登录”作为正式的数据同步方案，而不是临时调试功能：

1. 用户在 QQ 音乐网页版正常登录，并自行从浏览器开发者工具复制 Cookie。
2. 用户在 MoodMusic 设置页粘贴 Cookie；前端只把它提交给绑定环回地址的本机 FastAPI。
3. 后端验证 Cookie，提取运行请求所需的最小字段，并通过 Windows Credential Manager 或 DPAPI 保护的凭据存储保存；业务数据库只保存凭据引用、状态和去敏账号信息。
4. `QQMusicLibraryProvider` 使用该凭据调用经过审查的只读内部接口，分页读取“我喜欢”并转换为稳定的内部歌曲模型。
5. Cookie 过期或被撤销时停止同步，提示用户重新粘贴；不自动模拟登录，也不收集 QQ 密码。
6. 浏览器扩展继续承担网页播放控制，不负责首版音乐库同步。

二维码登录可以在首版稳定后另立 ADR 评估，但不得成为手动 Cookie 方案上线的阻塞项。

## 已知实现依据（不是稳定合约）

社区调研表明，当前“我喜欢”通常通过 `POST https://u.y.qq.com/cgi-bin/musicu.fcg` 请求，请求信封使用 `music.srfDissInfo.DissInfo / CgiGetDiss`，关键参数包含 `disstid=0`、`dirid=201`、`song_begin`、`song_num` 和当前用户标识。实现必须用项目所有者自己的账号做只读原型验证，不能把这些参数当成腾讯承诺的公开稳定合约。

参考实现仅用于理解协议边界：

- [ylw1997/qqmusic-api：获取我喜欢的歌曲](https://github.com/ylw1997/qqmusic-api/blob/master/docs/apis/get-my-favorite.md)
- [L-1124/QQMusicApi](https://github.com/L-1124/QQMusicApi)
- [simple-music：QQ Music API 调研](https://github.com/Yyyangshenghao/simple-music/blob/master/docs/qq-music-api.md)

不得直接复制第三方实现代码后忽略许可证。尤其 `L-1124/QQMusicApi` 和其他 GPL 项目在采用为依赖或复制实现前，必须完成许可证影响评审。

## 方案比较

| 方案 | 选择 | 原因 |
| --- | --- | --- |
| 手动复制 Cookie 到本机后端 | 采用 | 最短路径，适合个人单机使用，可完成登录验证和完整分页同步 |
| 浏览器扩展逐页读取 DOM | 作为回退，不作为主同步 | 不接触 Cookie，但滚动、虚拟列表和页面结构使全量同步更脆弱 |
| 模拟 QQ/微信二维码登录 | 后续评估 | 体验更好，但协议、设备信息和凭据刷新维护成本高 |
| 官方商业或 IoT 授权 | 保留未来可能 | 边界更清晰，但不能假设个人项目具备申请资格 |
| 音频直链、代理、下载或解密 | 不采用 | 超出选歌需求并扩大内容保护与账号风险 |

## 技术约束

- FastAPI、凭据代理和 Cookie 设置端点只监听 `127.0.0.1`；不得默认开放局域网或公网。
- Cookie 不写入 PostgreSQL 业务表、`.env`、浏览器持久化、日志、错误响应、测试快照或 Git。
- 设置响应只返回 `configured`、`valid`、`expiresAt`（可确定时）和去敏账号标识，永不回显原值。
- 适配器必须设置超时、低并发、分页上限、退避和可取消同步；禁止高频抓取。
- QQ 音乐请求、字段映射和错误分类集中在 `QQMusicLibraryProvider`，核心域只接收规范化模型。
- 首版适配器只允许登录验证、用户基本状态和“我喜欢”读取；任何平台写操作必须另行评审。
- Cookie 和 API Key 采用统一凭据抽象，但使用不同凭据名称和独立删除操作。
- 模型调用永远不得接收 Cookie、QQ 账号标识或第三方原始响应。

## 风险与缓解

- Cookie 过期：提供状态检查、明确的重新粘贴入口和幂等恢复，不伪装为系统故障。
- 私有接口变化：版本化适配器与响应契约样本，失败时保留旧曲库并允许 CSV 导入。
- 本机恶意进程：操作系统凭据保护不能抵御当前用户权限下的所有恶意软件；项目不夸大安全保证。
- 意外泄漏：建立日志字段拒绝列表、诊断包脱敏、秘密扫描和一键清除凭据。
- 平台边界：保持个人自用、低频、只读；分发、多人使用或商业化前重新审查平台条款和授权方式。

## 后果

音乐库同步与网页播放成为两个独立能力：前者由 Python 数据适配器完成，后者由 Manifest V3 扩展完成。这样提高了完整同步的可实现性，也引入了私有接口兼容和本机 Cookie 保管责任；这些风险必须由隔离适配、凭据保护和回退路径承担。
