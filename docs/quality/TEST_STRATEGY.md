# MoodMusic 测试与质量策略

## 1 质量结论

MoodMusic 的主要风险不是页面能否显示，而是选歌是否符合意图、集合是否严格来自“喜欢”、画像是否可信、连接器是否安全操作 QQ 页面，以及长任务是否能恢复。因此测试金字塔必须同时覆盖确定性代码、模型评测、跨模块合约和人工听感。

## 2 测试层级

### 2.1 单元测试

重点覆盖：

- 歌曲身份规范化、重复与不同版本判断。
- 画像 schema、置信度、缺失原因和人工锁定合并。
- 查询意图中的包含、排除和程度解析结果校验。
- 综合评分、均衡阈值、边界区间和全量集合输出。
- 匹配度、情绪曲线和带种子的随机排序。
- 预算计算、重试退避、checkpoint 和任务状态机。
- 日志脱敏、凭据访问边界、QQ 音乐只读接口 allowlist、URL allowlist 和连接器消息验证。

### 2.2 集成测试

使用临时 PostgreSQL 和 fake providers 验证：

- Alembic 从空库升级到最新版本。
- 导入批次、成员变更与画像任务事务一致性。
- pgvector 精确查询与应用层全量评分一致。
- worker 崩溃、租约过期、恢复和重复消息幂等。
- 搜索会话固定模型、画像和候选快照版本。
- API Key 和 QQ 音乐 Cookie 只通过凭据抽象访问，不进入业务数据库或响应。
- Cookie 写入、替换、登录验证、过期、撤销和清除不会在日志、任务载荷或异常中泄漏原值。
- QQ 音乐响应映射、分页、重复页、空列表、部分失败和接口结构变化使用匿名契约样本验证。

### 2.3 合约测试

- OpenAPI 与生成的 TypeScript/Python 类型一致。
- 连接器每种消息都通过 JSON Schema 正反例。
- 支持协议版本范围、能力协商、超时和未知消息处理。
- API 与连接器对相同 requestId 的重复命令保持幂等。
- 浏览器适配器 fixture 覆盖正常、缺失、重复和未知页面结构。

### 2.4 端到端测试

Playwright 与本地 fake QQ 页面覆盖：

- 首次设置、Cookie 粘贴与验证、“我喜欢”同步、手动导入回退、画像进度和恢复。
- 自然语言搜索、0 结果、追加要求和删除候选。
- 三种排序保持候选集合一致。
- 播放连接器配对、队列播放、断线和结束后停止。
- 外部建议独立展示与人工加入标记。
- 历史回放和队列清单导出失败回退。

真实 QQ 音乐账号只执行受控的人工兼容测试，不把真实账号、Cookie、原始接口响应或页面快照提交到仓库。

## 3 AI 评测

### 3.1 黄金提示集

建立至少 30 条代表性提示，覆盖：

- 单一气氛。
- 复合感觉。
- 否定条件，例如“孤独但不要太悲伤”。
- 场景，例如夜晚开车、通勤、学习或睡前。
- 律动、能量、BPM 与步频需求。
- 语言与风格，但仍以整体感觉为主。
- 应合法得到 0 首的严格请求。

每条提示由用户对候选进行适合、不适合和严重反向标注。黄金集不得只由模型自己生成和评分。

### 3.2 指标

- 候选人工准确率：通过候选中被用户认定适合的比例，目标至少 85%。
- 严重反向误判：违反明确排除或情绪方向的候选数，必须为 0。
- 集合纯度：主候选来自当前喜欢集合的比例，必须为 100%。
- 空结果正确性：要求无匹配时不自动放宽，必须通过所有案例。
- 稳定性：同模型、同画像、同参数和同随机种子产生相同候选快照。

召回率需要用户标注“所有本应匹配的歌曲”，成本较高。首版先通过抽样完整评审和全量算法审计判断，不伪造精确召回数字。

### 3.3 模型升级门槛

模型、提示模板、Embedding 或评分参数变化时：

1. 在固定黄金集上运行旧版与新版。
2. 比较准确率、严重反向误判、0 结果、成本和耗时。
3. 检查画像字段漂移和人工锁定是否保持。
4. 未达到门槛时不切换活动版本。
5. 保存去敏结果和版本信息以便回滚。

## 4 连接器兼容性测试

最小测试矩阵：

- 目标 Chromium 浏览器的当前稳定版本。
- QQ 音乐页面浅色与深色主题，如果页面实际支持且影响 DOM。
- 喜欢列表为空、少量和一千以上歌曲。
- 歌曲不可播放、同名多版本、多歌手和无专辑信息。
- 页面未登录、加载中、弹窗遮挡、元素重复和结构未知。
- 播放中断、人工切歌、断网、标签页关闭和扩展重启。
- PC 连接器覆盖 QQ 音乐客户端版本探测、窗口/控件歧义、最小化与遮挡、焦点变化、媒体会话缺失和安全停止。
- 相同队列快照分别提交给网页与 PC 连接器时，能力协商、幂等语义、歌曲身份和顺序校验使用同一组契约案例。

任何未知页面结构都应停止操作，不允许为了测试通过而增加宽泛选择器。

只读数据适配器另行覆盖：

- Cookie 缺失、格式错误、有效、过期和被撤销。
- “我喜欢”为空、单页、多页、一千首以上、重复页和总数中途变化。
- 字段缺失、同名多版本、多歌手、不可播放项和响应 schema 变化。
- 429、超时、断网和部分分页失败后继续；失败不得清空最近一次成功曲库。
- allowlist 之外的写接口、音频 URL 和下载能力默认不可调用。

## 5 安全测试

- `.env`、业务数据库、浏览器存储、任务载荷、历史提交、构建产物、诊断包和日志秘密扫描。
- CORS、Origin、CSRF、WebSocket 配对、令牌撤销和重放测试。
- 超长输入、巨大消息、路径、URL 和重定向验证。
- 歌曲元数据与搜索网页中的提示注入测试。
- 日志对 Authorization、Cookie、API Key、QQ 标识和 URL 的脱敏测试。
- QQ 音乐凭据端点只允许环回访问，写入响应不回显秘密，清除后无法再次解密。
- 扩展权限最小化与未知页面 fail-closed 测试。

## 6 性能与恢复测试

- 一千以上歌曲导入、全量精确评分和历史保存基准。
- 模型并发、429、超时、部分批次失败和预算停止。
- worker 在不同 checkpoint 被强制终止后恢复。
- PostgreSQL 暂时不可用、磁盘不足和迁移失败回滚。
- 50 次冷启动和不少于 8 小时播放状态跟踪。
- 连接器多次断线重连不重复提交队列。

## 7 发布质量门

首版发布需要：

- 所有自动化测试通过，没有跳过的核心测试。
- 黄金集达到 PRD 指标。
- 数据迁移、备份、恢复、卸载和秘密清理验证完成。
- 连接器真实页面人工兼容测试通过并记录目标版本。
- 候选集合、预览顺序和实际播放顺序抽样一致。
- 安全清单与依赖许可证检查通过。
- README、PRD、ADR、API、数据模型和 CHANGELOG 与实现一致。
