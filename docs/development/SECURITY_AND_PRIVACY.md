# MoodMusic 安全与隐私基线

## 1 安全结论

MoodMusic 采用本地优先和最小权限。用户手动提供的 QQ 音乐 Cookie 与模型 API Key 均由本机操作系统凭据存储保护，不写入项目文件、业务数据库或前端持久化。MoodMusic 只保存完成业务所需的歌曲身份、喜欢成员关系、画像、搜索历史、凭据引用和去敏运行信息。

## 2 受保护资产

- 用户的 QQ 登录态、Cookie、账号标识和会员权益。
- 聊天、Embedding 和外部搜索提供方 API Key。
- 喜欢歌曲列表、搜索描述、临时反馈和历史队列。
- 用户明确修改并锁定的歌曲画像。
- 受版权保护的音频、歌词和播放地址。
- 本机连接器配对令牌。

## 3 信任边界

| 边界 | 允许通过 | 禁止通过 |
| --- | --- | --- |
| 用户到本机 API | 用户主动粘贴的 QQ 音乐 Cookie、模型 API Key | QQ 密码、受保护音频、无关浏览器数据 |
| 本机凭据代理到 QQ 音乐适配器 | 按名称短时读取所需凭据 | 把秘密复制到业务数据库、任务载荷或日志 |
| QQ 音乐适配器到 QQ 音乐 | Cookie、必要请求参数、低频只读请求 | 密码、模型 API Key、音频下载或解密请求 |
| QQ 页面到播放扩展 | 歌曲身份、用户触发状态、播放状态 | 密码、Cookie、受保护播放地址、原始音频 |
| 播放连接器到本机 API | 连接器类型、版本化能力、去敏错误、播放事件 | 浏览器/客户端存储全文、页面 HTML、QQ 登录令牌、窗口内容快照 |
| 本机到模型 | 最小必要歌曲元数据、摘要、用户搜索描述 | QQ 账号、Cookie、API Key、原始音频、无关历史 |
| 本机到外部搜索 | 规范化歌曲查询、最小上下文 | 用户身份、完整喜欢列表、密钥以外的本机配置 |
| 日志 | requestId、版本、耗时、错误类别、用量 | Authorization、Cookie、密钥、播放 URL、歌词全文、原始音频 |

## 4 凭据管理

- API Key 与 QQ 音乐 Cookie 分别写入 Windows Credential Manager，或使用 Windows DPAPI 保护的等价本机凭据存储。
- 数据库只保存随机凭据引用 ID、提供方、验证状态、可确定的过期时间和掩码信息。
- Web 页面提交密钥时使用本机 HTTPS 开发证书或仅绑定环回地址的受控通道；响应永远不回显原值。
- 前端不把密钥写入 localStorage、sessionStorage、IndexedDB、React 状态持久化或错误监控。
- 删除提供方配置或点击“清除 QQ 登录”时同步删除对应操作系统凭据。
- `.env.example` 只记录变量名称；真实 `.env*` 已被 Git 忽略。

### 4.1 QQ 音乐 Cookie 的附加约束

- Cookie 只能由用户主动粘贴；应用不接收 QQ 密码，不注入浏览器窃取 Cookie。
- Cookie 设置端点不得返回、记录或通过错误监控转发原值；前端提交成功后立即清空输入状态。
- 后端只提取请求必需字段，不把浏览器 Cookie 全文放入任务队列、缓存、数据库或诊断包。
- 登录检查只返回 `configured`、`valid`、去敏账号标识、检查时间和可确定的过期状态。
- 后端仅在发起受审查的 QQ 音乐只读请求时短时解密凭据，使用后释放引用。
- 当前 Windows 用户权限下的恶意进程仍可能窃取正在使用的秘密；DPAPI 不是对本机失陷的完整防护。

## 5 QQ 音乐数据适配器与播放连接器安全

数据适配器：

- QQ 音乐内部请求集中在版本化 `QQMusicLibraryProvider`，只向核心域返回规范化歌曲和去敏错误。
- 首版 allowlist 只包含登录状态、用户基础状态和“我喜欢”分页读取；默认拒绝写歌单、收藏变更、音频 URL、下载和解密能力。
- 设置合理的分页上限、低并发、超时、退避和取消机制，避免高频请求。
- 私有接口响应只用于内存解析；默认不持久化原文。契约夹具必须最小化、匿名化且不含 Cookie。

播放连接器：

- 网关仅监听 `127.0.0.1`，不默认监听 `0.0.0.0`。
- 使用短时一次性配对码，换取随机高熵、可撤销的安装级令牌。
- 配对令牌不通过 URL query、日志或页面 DOM 长期暴露。
- 验证扩展声明的协议版本、Origin、安装 ID 和消息 schema。
- 对同步、搜索和播放命令设置频率、超时、最大消息大小和并发限制。
- PC 连接器不得注入 QQ 音乐进程、读写其内存、修改客户端文件或截获播放地址；只允许系统媒体能力、媒体键以及客户端安装程序明确注册到 Windows 的自动化接口。
- 客户端注册的 COM 接口按版本和方法 allowlist 使用；下载、上传、登录、收藏变更、歌词写入及其他无关成员默认拒绝。
- PC 客户端版本未知、COM 返回歧义或能力探测失败时必须停止自动化，并允许用户人工打开或搜索歌曲。
- DOM 目标不唯一、页面版本未知或状态不明确时 fail closed。
- 不使用脚本绕过登录、会员、地区、版权或 DRM 限制。

## 6 Web 与 API 安全

- CORS 只允许配置的本机 Web Origin。
- 状态改变请求采用 Origin 校验和 CSRF 防护。
- 所有输入设置长度、数量和 schema 限制。
- 前端展示歌名、歌手、错误和模型输出时默认转义，不插入不可信 HTML。
- SQL 通过 SQLAlchemy 参数化，不拼接用户输入。
- 外部 URL 只允许 `https` 和审核过的域；防止 SSRF、重定向滥用和本机地址访问。
- 依赖锁定并定期审计；高危漏洞阻止发布。

## 7 AI 特有风险

- 歌曲元数据、歌词摘要和网页内容都视为不可信数据，不得作为系统指令执行。
- 模型只返回严格 schema；解析失败进入重试或人工检查，不能宽松写库。
- 联网搜索结果中的提示注入、脚本和链接不传递为高权限指令。
- 用户描述不会授权模型扩大主候选范围或改变安全策略。
- 模型输出的歌曲身份必须经过数据库或曲库校验。
- 记录模型与提示模板版本，支持回滚和差异评测。

## 8 数据最小化与保留

- 默认不保存完整歌词，只保存为检索所需的结构化摘要和来源引用。
- 默认不保存 QQ 页面 HTML、截图、网络响应、Cookie 明文或播放链接。
- 原始用户搜索描述用于历史功能；用户可以删除单条或全部历史。
- 取消喜欢只保留恢复和历史一致性需要的最小标记。
- 调试日志轮换并提供一键清理。
- 任何遥测默认关闭；未来新增必须明确 opt-in 并通过 ADR。

## 9 音频处理

- 首版不能以完成画像为由强制访问音频。
- 只有用户有权处理、平台正常授权播放且技术路径不绕过保护时，才允许内存内临时分析。
- 原始 PCM 不落盘、不写日志、不上传模型，分析后立即释放。
- 无可靠音频时，声学字段保持未知；语义选歌可以继续运行。

## 10 事件响应与恢复

发现密钥或登录态泄露时：

1. 停止相关服务、数据适配器和播放连接器。
2. 撤销受影响密钥、配对令牌和会话。
3. 保存去敏时间线，不复制秘密到工单。
4. 检查 Git 历史、日志、浏览器存储和数据库。
5. 修复根因并增加回归测试。
6. 如果秘密进入 Git 历史，使用专门清理流程并完成远端轮换；不能只删除当前文件。

## 11 发布检查

- Git 和构建产物秘密扫描通过。
- 日志与诊断包脱敏测试通过。
- QQ 音乐 Cookie 可以保存、验证、替换和彻底清除，且不会出现在数据库、日志、诊断包或构建产物中。
- 浏览器扩展权限与实际播放能力一致，没有多余 host permission；PC 助手权限与进程访问范围保持最小化。
- 安装、撤销配对、清理数据和卸载路径验证完成。
- 依赖许可证与分发边界完成审查。
- QQ 音乐接入方式没有越过当前批准的产品边界。
