# MoodMusic 编码规范

## 1 通用规范

- 文件使用 UTF-8 和仓库 `.editorconfig` 定义的换行及缩进。
- 产品文档、界面文案和面向用户的错误信息使用中文。
- 代码标识符、API 字段、数据库名称和提交类型使用清晰英文。
- 时间存储为 UTC；金额、用量和比例使用明确单位。
- 不使用模糊缩写，例如 `data1`、`tmp2`、`mgr`；领域名称应能对应文档。
- 注释解释原因、约束或风险，不逐行复述代码。

## 2 TypeScript 与 React

- 开启 TypeScript strict 模式，禁止无理由的 `any`。
- 共享外部输入先通过 schema 验证，不使用类型断言跳过验证。
- React 组件按页面、功能和通用 UI 分层；业务规则不写进展示组件。
- Server 与 Client Component 边界显式，只有需要交互或浏览器能力时使用 Client Component。
- 数据获取集中在服务层；不得在组件中直接拼接 API URL 和错误处理。
- 浏览器扩展页面适配与连接器协议分离，DOM 类型不得进入共享契约。

计划工具：ESLint、Prettier、Vitest、React Testing Library 和 Playwright。具体版本在创建实际工程时锁定。

## 3 Python 与 FastAPI

- 使用 Python 类型标注，公开函数和领域对象不得依赖未标注字典。
- Pydantic 模型负责外部边界；SQLAlchemy 模型不直接作为 API 响应。
- 路由只处理鉴权、验证、调用应用服务和映射响应。
- 领域服务不依赖 FastAPI request 对象。
- 数据库事务边界由应用服务控制，不在工具函数中隐式提交。
- 网络和模型调用设置明确超时，不执行无限重试。
- 长任务在独立 worker 运行，不占用 API 请求进程。

计划工具：Ruff、mypy、pytest 和 Alembic。具体版本在创建实际工程时锁定。

## 4 SQL 与迁移

- 表名和列名使用 `snake_case`。
- 外键、唯一约束和常用查询索引显式命名。
- 所有查询必须明确排序，分页不能依赖数据库自然顺序。
- JSONB 只用于真正变化的结构，核心过滤字段使用正常列或关系表。
- 向量维度和索引策略由选定模型与基准测试决定，不提前硬编码。

## 5 API 与契约

- URL 使用复数资源名，动词只用于明确命令子资源。
- JSON 使用 `camelCase`。
- 所有写命令可追踪 `requestId`，高风险重试写入使用幂等键。
- 错误码稳定、机器可读；错误信息不暴露第三方响应、SQL、路径或秘密。
- 连接器消息必须带协议版本、请求 ID、时间戳和 schema 校验。

## 6 测试代码

- 测试名称描述行为和条件，不复述函数名。
- 每个缺陷先建立失败回归测试，再修复代码。
- 不在普通测试中访问真实 QQ 账号或产生真实模型费用。
- 随机排序固定 seed；时间相关测试使用可控时钟。
- 测试数据使用虚构歌曲和用户，不复制真实账号页面。

## 7 禁止事项

- 禁止提交密钥、Cookie、真实账号导出、歌词全文、音频或播放 URL。
- 禁止静默捕获异常后返回空数组。
- 禁止把 `unknown` 改写为模型猜测值。
- 禁止把候选集合的 Top-K 检索结果直接当作最终通过集合。
- 禁止用 CSS selector 或第三方 SDK 类型穿透核心域边界。
- 禁止在没有 ADR 的情况下引入新数据库、队列或框架。
