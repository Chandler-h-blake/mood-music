# MoodMusic 开发指南

## 1 开发目标

本指南规定如何在不破坏产品、数据和安全边界的前提下持续开发 MoodMusic。当前仓库已经包含可运行的 Next.js Web、FastAPI API、PostgreSQL/pgvector 曲库、DeepSeek 画像、本地 BGE-M3 向量、自然语言选歌和临时队列链路；播放连接器与外部发现仍在后续阶段。经过本机验证的启动命令以仓库 README 为准。

## 2 前置工具策略

预计需要：

- Git
- Node.js LTS 与包管理器
- Python 稳定版本与项目级虚拟环境
- Docker Desktop 或兼容的容器运行时
- Chromium 系浏览器
- 可选的 PostgreSQL 客户端

所有新增工具先检查机器是否已有可用版本。只有缺失或版本不兼容时才安装；安装位置、磁盘占用和环境变量变更必须先记录并得到项目所有者确认。不得因为文档渲染需求安装与运行项目无关的大型软件。

Python 使用独立虚拟环境。可以使用 `venv`、`uv` 或现有 Conda，但仓库只能依赖标准清单和锁文件，不能依赖个人全局环境。

## 3 分支与提交

- 默认分支：`main`。
- 功能分支：`feat/<short-name>`。
- 修复分支：`fix/<short-name>`。
- 文档分支：`docs/<short-name>`。
- 重构分支：`refactor/<short-name>`。

提交使用 Conventional Commits：

```text
feat(search): add balanced boundary review
fix(connector): stop when page capability probe fails
docs(product): clarify zero-result behavior
test(profile): cover locked field rebuild
```

一次提交只解决一个可以说明和回退的问题。不得把格式化全仓库、依赖升级和功能实现混在同一提交。

## 4 本地工作流

当前使用 README 中分开的 Docker、API 和 Web 命令启动。统一 PowerShell 入口仍是 M1 的工程欠账，完成后应提供：

1. `setup`：检查版本、建立虚拟环境、安装锁定依赖。
2. `dev`：启动 PostgreSQL、API、worker 和 Web。
3. `lint`：格式、静态类型和契约漂移检查。
4. `test`：单元与集成测试。
5. `test-e2e`：启动隔离环境运行 Playwright。
6. `build`：产生 Web、API 和扩展可重复构建。

Windows 应提供 `scripts/*.ps1`，CI 可使用等价跨平台命令。每条脚本失败时返回非零退出码，不隐藏错误。

## 5 需求到交付

每项功能按以下顺序进行：

1. 在 PRD 中找到对应业务规则和验收标准。
2. 判断是否影响架构、数据、API、安全或 QQ 页面兼容；需要时先写 ADR。
3. 先补充或修改契约与测试案例。
4. 实现最小的领域逻辑，再连接数据库、第三方提供方和 UI。
5. 运行相关单元、集成、合约和端到端测试。
6. 更新 README、CHANGELOG 和用户可见文档。
7. 确认日志、错误和样例不包含敏感数据。

## 6 数据库迁移

- 所有 schema 修改通过 Alembic 完成。
- 已进入 `main` 的迁移不得原地重写，使用新迁移修正。
- 迁移同时提供升级、降级可行性说明和数据影响。
- 大批量画像重建与数据库 schema 迁移分离，避免应用升级被模型调用阻塞。
- 测试必须从空库执行全部迁移，并从上一发布版本验证升级路径。

## 7 第三方提供方

- 所有模型和搜索 SDK 封装在 `providers` 适配器中。
- 业务代码依赖内部接口，不依赖具体厂商响应。
- 模型输出先过 schema、枚举和范围校验，再写入候选或画像版本。
- 处理 429、超时、网络失败和部分批次失败，重试必须有上限与退避。
- 测试默认使用录制后脱敏的契约样本或 fake provider，不产生真实费用。

## 8 QQ 音乐接入开发

### 8.1 只读数据适配器

- 真实 Cookie 只能由项目所有者在本机设置页输入，不放入命令行参数、源代码、`.env`、fixture 或调试脚本。
- 数据适配器通过凭据引用读取 Cookie；核心业务和任务消息不得传递 Cookie 字符串。
- QQ 音乐 URL、请求参数、分页、响应映射和错误分类集中在版本化 Provider 中。
- 首版 allowlist 仅包含登录验证、用户基础状态和“我喜欢”读取；增加写操作、二维码登录、设备模拟或音频能力前必须新增 ADR。
- 调试第三方响应时先最小化和匿名化，删除 Cookie、QQ 标识、个人歌单内容和受保护 URL 后才能形成测试样本。
- 适配器必须限制并发、设置超时与退避；失败保留最近一次成功曲库，并提供 CSV 导入回退。

### 8.2 网页与 PC 播放连接器

- 只在测试账号与测试数据上开发页面适配器。
- DOM selector 集中在版本化页面适配器中。
- 先探测页面版本、关键元素和能力，再执行读取或点击。
- 未知结构、重复匹配、遮挡或状态不明确时停止，并输出去敏诊断。
- 不提交 QQ 页面完整快照中的个人信息；回归 fixture 必须最小化并匿名化。
- 播放扩展不提取 Cookie，不截获受保护音频地址；它与只读数据适配器保持独立。
- PC 连接器只允许使用系统媒体能力、媒体键、窗口级公开消息或客户端安装程序注册的自动化接口；禁止注入进程、读取内存、修改客户端文件或提取受保护播放地址。
- 网页与 PC 连接器共享领域命令、能力名称、幂等语义和错误分类，但页面选择器与桌面控件定位器必须分开维护。
- PC 能力无法可靠探测、COM 返回不明确或客户端版本未知时必须停止自动化，并提示用户人工打开或搜索歌曲；Chrome 路线当前暂停。

## 9 Definition of Done

一项功能只有同时满足以下条件才完成：

- 满足 PRD 和任务中的验收条件。
- 正常、空输入、失败、取消和重试路径得到处理。
- 单元、集成或端到端测试覆盖风险点。
- API、数据和 UI 文案保持一致。
- 无新增明文密钥、个人数据或受保护内容。
- 日志可定位问题但已脱敏。
- 用户文档、CHANGELOG 和必要 ADR 已更新。
- 本地与 CI 构建通过，没有未解释的警告。

## 10 文档优先级

冲突处理顺序：

1. Accepted ADR
2. SYSTEM_DESIGN
3. PRD
4. API_CONTRACT 与 DATA_MODEL
5. README
6. 代码注释

如果代码与高优先级文档冲突，应停止扩展实现，先确认事实并更新正确的决策来源。
