# MoodMusic 首版实施路线图

## 1 交付策略

首版包含完整功能范围，但不采用一次性大爆炸开发。每个阶段都是内部质量门，只有全部阶段通过后才发布首个可用版本。任何阶段未满足退出条件，都不得通过“先留 TODO”绕过影响核心闭环的问题。

## 2 阶段与退出条件

当前进度（2026-09-13）：M0 已完成；M1 的 Next.js 曲库工作台、FastAPI、PostgreSQL/pgvector、Alembic、健康检查和真实音乐库持久化已完成；M2、M3 的核心链路和 M4 候选编辑、三种排序、追加要求、历史回放已完成；M5 的 Cookie 凭据与“我喜欢”全量/增量只读同步已提前完成。M1 的 CSV 回退、统一启动脚本和完整错误合约，M2/M3 的完整质量门，以及 M5 的 Chrome 网页与 PC 播放连接器仍未完成。

### M0 项目基线

主要工作：

- 初始化 Git、目录、文档优先级和变更记录。
- 固化产品范围、架构边界、安全边界和测试策略。
- 确认 Node.js、Python、PostgreSQL 和浏览器的实际版本后再生成工程清单。

退出条件：

- README、PRD、系统设计、数据模型、API 合约、开发规范和测试策略互相一致。
- 仓库不包含 QQ 音乐二进制、密钥、登录态或真实用户数据。
- 首次基线提交可在本地读取，Git 默认分支为 `main`。

### M1 音乐库与基础界面

主要工作：

- 创建 Next.js Web 和 FastAPI API 工程。
- 建立 PostgreSQL、Alembic 迁移、健康检查与本地开发命令。
- 实现 CSV 导入、歌曲去重、喜欢成员关系和音乐库页面。
- 建立合约生成、错误模型、日志脱敏与基本测试。
- 实现操作系统凭据抽象、QQ 音乐 Cookie 设置/验证/清除和只读 Provider 骨架。

退出条件：

- 重复导入幂等，错误行进入待确认区。
- 新增、取消喜欢和版本信息可被正确持久化。
- 开发环境可以通过一条统一命令启动和一条统一命令验证。
- Cookie 不进入业务数据库、日志、前端持久化、测试夹具或 Git。

### M2 完整画像与后台任务

主要工作：

- 落实画像 schema、字段证据、置信度、模型版本和人工锁定。
- 实现聊天模型与 Embedding 提供方适配器。
- 实现批次、并发、预算估算、暂停、继续、取消、重试和 checkpoint。
- 对新增歌曲和模型版本变化执行增量重建。

退出条件：

- 每首已完成歌曲具有完整字段结构，未知值有明确原因，不存在伪造占位。
- 任务在进程重启后可以恢复，不覆盖人工锁定字段。
- API Key 不出现在数据库、配置文件、前端 bundle 或日志。

### M3 自然语言选歌

主要工作：

- 实现意图解析、向量检索、连续特征评分、均衡阈值和边界复核。
- 实现全量候选集合、合法 0 结果和查询版本追踪。
- 建立不少于 30 条提示的黄金评测集和人工打分流程。

退出条件：

- 不使用固定 Top-K 截断。
- 所有主结果属于当前喜欢集合，外部数据自动混入为 0。
- 评测集候选人工准确率达到 85% 目标，严重反向情绪误判为 0。

### M4 候选编辑与三种排序

主要工作：

- 实现候选预览、删除、拖动、找相似和会话内追加要求。
- 实现匹配度、情绪曲线和带种子的随机排序。
- 实现搜索历史、临时队列历史和可回放版本信息。

退出条件：

- 三种排序只改变顺序，不改变候选集合。
- 临时反馈不形成长期偏好，人工画像修改才可长期保存。
- 历史记录可以重建当时的候选集合和排序。

### M5 QQ 音乐同步与双播放连接器

主要工作：

- 完成 QQ 音乐 Cookie 设置、验证、替换、清除和过期提示。
- 实现只读内部接口适配器、“我喜欢”分页同步、响应映射、增量更新和 CSV 回退。
- 创建 Manifest V3 播放扩展、配对协议、能力协商和连接状态页面。
- 实现歌曲定位、队列提交与播放状态回传。
- 实现页面兼容性探测、集中选择器、断线重连和安全停止。
- 验证最后一首结束后停止。
- 建立与具体播放器无关的连接器网关和版本化能力协议，允许用户在网页与 PC 连接器之间选择。
- 对 QQ 音乐 PC 客户端执行只读的 UI Automation、窗口消息、媒体键与公开系统能力探测，形成版本化可行性报告。
- 仅在探测证明可可靠定位歌曲、保持队列顺序并读取必要状态后实现 PC 本地助手；禁止 DLL 注入、内存读写、客户端文件修改和受保护音频提取。

退出条件：

- QQ 密码从未进入应用；Cookie 只存在于操作系统凭据存储和单次请求内存，不出现在数据库、日志、诊断包或模型请求。
- 同步数量、身份与 QQ 音乐“我喜欢”页面抽样核对一致；Cookie 过期和接口变化不会破坏最近一次成功曲库。
- 候选顺序、预览顺序与实际播放顺序一致。
- 页面结构未知时停止操作并报告错误，不发生盲目点击。
- 两类连接器分别报告能力；PC 探测不通过时明确降级到 Chrome 扩展或人工跳转，不能伪报成功。

### M6 外部发现与队列导出

主要工作：

- 实现真实联网搜索、身份与版本校验、可播放状态检查。
- 实现独立外部建议区域和人工加入标记。
- 实现 JSON、CSV 或 M3U 队列清单导出，不通过私有接口写入 QQ 音乐账号。

退出条件：

- 不存在虚构歌名、歌手或版本进入可见结果。
- 外部建议永远不会自动混入主候选或播放队列。
- 导出失败不破坏临时队列与历史。

### M7 加固与首版交付

主要工作：

- 完成单元、集成、合约、端到端、安全和恢复测试。
- 完成 50 次冷启动、长时间播放和故障注入验证。
- 生成可重复构建、依赖清单、许可证清单、安装、升级、卸载和诊断文档。
- 审查 QQ 音乐页面接入方式和项目分发边界。

退出条件：

- PRD 第 8 节全部标准通过并保留测试证据。
- 普通 Web、API 或模型故障不影响 QQ 音乐页面正常使用。
- 清除凭据、移除扩展和 MoodMusic 数据后，QQ 音乐仍按原方式工作。

## 3 变更管理

- 核心业务规则变化先更新 PRD，再开发代码。
- 跨进程边界、持久化策略、第三方接入或基础设施变化必须新增 ADR。
- 模型变化记录模型 ID、提示模板版本、画像版本和评测差异。
- QQ 音乐页面变化建立兼容性记录，不能仅修改选择器后跳过回归测试。
